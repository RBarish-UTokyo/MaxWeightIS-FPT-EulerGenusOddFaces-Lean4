# An FPT algorithm for maximum-weight independent set in embedded graphs, in Lean 4

A Lean 4 and Mathlib formalization of a fixed-parameter theorem of
*Maximum-weight independent set in embedded graphs parameterized by Euler genus
and number of odd faces* (forthcoming), together with a provably correct
implementation of the algorithm as one fixed program for an explicit pointer
machine.

* **What Lean proves.** There is one fixed finite program and one absolute
  constant `c` such that, for every graph drawn in a closed surface of Euler
  genus `γ` whose complement has `k` regions of odd total boundary length, and
  for all integer vertex weights, the program outputs a maximum-weight
  independent set using at most
  `2 ^ (c · (p · size p + 1)) · (N · size M) ^ c` bit operations, where
  `p = γ + k`, `N = |V| + |E| + 1`, `M = max(1, max_v |w_v|)` and
  `size x = ⌈log₂(x + 1)⌉`. This is `2^{O(p log(p+1))} · poly(N, log(M+1))`
  with an absolute polynomial exponent.
* **Axioms.** The proof uses exactly Lean's three standard axioms
  (`propext`, `Classical.choice`, `Quot.sound`). There is no `sorry`, no other
  axiom and no `native_decide`.
* **Checking.** The Lean kernel checks the proof; Comparator checks that the
  solution proves the challenge statement and replays it with the toolchain's
  independent kernels (see [Checking](#checking)). The recorded runs are local;
  official Palomar verification has not been performed.

Author and maintainer: Robert D. Barish (rbarish@ims.u-tokyo.ac.jp).

## The statement

The statement is [`Challenge.lean`](Challenge.lean), generated by
[`scripts/generate_challenge.py`](scripts/generate_challenge.py) as a verbatim
copy of the project modules [`MWIS/Statement.lean`](MWIS/Statement.lean) and
[`MWIS/FPTStatement.lean`](MWIS/FPTStatement.lean) (Mathlib imports only;
the unused inherited XP statement `MainClaim` is omitted), followed by the
target

```lean
theorem MWIS.Spec.fpt_claim : MWIS.Spec.FPTClaim
```

The proof is [`Solution.lean`](Solution.lean). The statement has four parts.

1. **The machine.** A sixteen-register pointer machine
   (`MWIS.RegisterMachine`): a program is a finite table of closed procedure
   bodies built from loads, bounded cell allocations, register copies, Boolean
   branches, procedure calls and returns. There is no arithmetic instruction on
   unbounded numbers and no host-function instruction. The interpreter
   `FramedExec` records every heap event and the caller frame saved at every
   call.
2. **The cost.** `stackBitCost` of the run's call tree: every heap event costs
   `4` plus the binary lengths of the addresses it reads or writes, and every
   call additionally pushes and later pops the caller's sixteen register words
   bit by bit on an explicit symbol stack. This is a logarithmic-cost measure
   of bit operations.
3. **Surfaces and drawings** (`MWIS.Spec`). A closed surface is given by a
   finite combinatorial *map*: a connected graph cellularly embedded in the
   surface, recorded by its flags (edge, side, endpoint) and the corner pairing
   of flags, which covers orientable and nonorientable surfaces. Faces are the
   orbits of flags under `along` and `corner`, and the Euler genus is
   `E + 2 − V − F`. The input graph is a `Drawing` (possibly disconnected,
   noncellular, with loops, multiple edges and isolated vertices) together with
   a witness `D.In A` that it is a subdrawing of a closed-surface map `A`.
   Complementary regions are the faces of `A` glued across the deleted edges.
   The parameter `k` counts the regions whose *total* boundary-walk length,
   with multiplicity, is odd.
4. **Input and output.** The input heap is produced by the fixed encoding
   `Spec.encode` of the drawing and of the integer weights, written as rationals
   with denominator one. The run must return a pointer to a list of vertex words
   denoting a maximum-weight independent set.

`FPTClaim` fixes the program and the constant before the input, and asserts
that the run exists, that every run returns a maximum-weight independent set,
and that every run satisfies the cost bound. Runs are deterministic. The
machine, cost, surface model and encoding are those of the registered entry
PALOMAR-2026-10-22-000006 v1.

### Modelling choices

* The ambient map is a proof witness only. The program reads the drawing and
  its rotation system with edge twists; the bound holds for every closed-surface
  map containing the drawing.
* `N = |V| + |E| + 1` counts the drawing only and is at most the encoding
  length, so the bound in `N` is the stronger form.
* The weights are integers. The rational-weight extension mentioned in the
  paper is not formalized.

## Constants

The program is `FPTProgram.fptProgram FPTRunFun.constsProg.encode
(FPTMainProg.prog FunLP.optF).encode`, a table of 402 procedure bodies,
started at its top-level entry. The constant `c` is an explicit numeral
assembled in the proof (`GenericAccounting.fptClaim_of_hard`,
`FPTMainProg.mainBudget_bound`, `FunLP.optF_cost`). It bounds the proof
and says nothing about the program's practical running time; the theorem asserts
only an absolute constant.

## Relation to the paper

The manuscript is forthcoming and is not included in this repository. The
program implements the paper's algorithm.

1. Truncate negative weights.
2. Compute a half-integral optimum of the fractional independent-set relaxation
   by an integral maximum flow on the double cover, keep the half-valued
   vertices, and split the residual graph into connected components. A
   bipartite component is solved by a colour class.
3. On a nonbipartite component:
   1. obtain nonnegative integer edge costs from the maximum flow;
   2. build the alternating even-face columns `B` by XP's face stage;
   3. compute exact integral quotient coordinates of `ker B / Aℤ^V ≅ ℤ^r × ℤ/2`
      from a spanning tree and elimination with unit pivots, with no normal
      form;
   4. perturb the costs to `2^(m+1) c_e + 2^e` and build the finite-group
      network LP of the quotient modulo `μ`, with group size at most
      `2 (4(p+1))^p`;
   5. compute its exact optimum by binary threshold search, deciding each
      threshold by a rounded ellipsoid method;
   6. decode the unique optimal binary slack from the low-order bits, and
      recover the independent set by propagation along a spanning tree (XP's
      odd-row and recovery stages).
4. Assemble the components, restore the fixed vertices, and remove the
   originally negative vertices.

The numerical stages, from the coordinates in 3.3 to the decoding in 3.6, run
as programs of a small total first-order language (`MWIS.Fun`) on a register
interpreter that is verified to stay within `2048` times the language's cost
measure. Steps 3.1, 3.2 and the recovery in 3.6 use XP's register procedures. The coarse convexity argument,
midpoint convexity by direct rounding of vertex potentials, the signed cover,
the finite-group network and its real-flow integrality are formalized as in the
paper. The rank bound `r ≤ γ + k` is applied to the coordinates the program
actually computes.

## Relation to the XP formalization

The registered entry PALOMAR-2026-10-22-000006 v1 proves an XP bound for the
same problem. This project reuses its statement surface and every stage of its
program except the hard-component solver. The new hard-component solver of
step 3 still calls XP's edge-cost, face, odd-row and recovery stages; its
coordinates, network LP, exact optimizer and decoding are new.
432 of its modules are included verbatim apart from the renaming of
`WeightedMIS` to `MWIS`; see [`PROVENANCE.md`](PROVENANCE.md). Its XP theorem is
not used for the fixed-parameter bound.

## Checking

The project pins Lean `leanprover/lean4:v4.35.0-rc2` and Mathlib commit
`065356127b1dc0016f66b7283ce0ce2c4055aa55`.

```sh
lake exe cache get
lake build AllModules MWIS Challenge Solution Audit
lake env lean Audit.lean                       # axioms of MWIS.Spec.fpt_claim
python3 scripts/check_sources.py               # hygiene and repository rules
python3 scripts/generate_challenge.py --check  # Challenge matches its sources
./scripts/verify.sh                            # all of the above and Comparator
```

`scripts/verify.sh` runs Comparator with NanoDa and con-ron as external kernels;
Comparator needs `bwrap`. The records of the local runs on the exact source
snapshot are in [`verification/`](verification/).

## Layout

* `Challenge.lean`, `Solution.lean`, `comparator.json`, `Audit.lean`: the
  Palomar statement, proof, Comparator configuration and axiom audit.
* `MWIS/Statement.lean`, `MWIS/FPTStatement.lean`: every definition the
  statement uses.
* `MWIS/`: the development (596 modules, all imported by the proof). Its main
  parts are:
  * the XP pipeline: max-flow preprocessing, components, capped embeddings,
    face columns, edge costs, parity rows, recovery and assembly;
  * the generic assembly with the hard solver as a parameter (`Generic*`);
  * the mathematics: class minima, midpoint convexity, coarse Jensen, the signed
    cover, the finite-group network and its integrality, exact coordinates
    (`TreeCotree*`), the rounded ellipsoid method and threshold search;
  * the fixed-parameter hard function (`FPTHard*`);
  * the `Fun` language, its register interpreter and its programs (`Fun/`,
    `FunCoordinates*`, `FunNetwork*`, `FunLP*`, `FPTMainProg*`);
  * the hard procedure, the concrete program table (`FPTProgram*`, generated by
    `scripts/gen_fpt_program.py`) and the final assembly (`FPTFinal`).
* `third_party/formalpedia/`: licence and provenance of the adapted ellipsoid
  feasibility proofs.
